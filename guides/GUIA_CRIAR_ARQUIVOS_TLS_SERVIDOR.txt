GUIA PARA CRIAR OS ARQUIVOS TLS NO SERVIDOR

Objetivo:
- criar a pasta de certificados no servidor
- criar os 2 arquivos que o frontend/nginx em HTTPS vai montar no container
- mostrar um exemplo concreto de como gerar os 2 arquivos no proprio servidor
- deixar um modelo simples para colar o conteudo depois

Arquivos esperados pelo compose novo:
- /etc/dcriar/tls/fullchain.crt
- /etc/dcriar/tls/private.key

Observacao:
- estes arquivos ficam no servidor
- eles NAO vao para o Docker Hub
- a imagem do frontend apenas monta esses arquivos por volume
- no nosso caso de teste, foi gerado um certificado autoassinado para o IP do servidor

==================================================
PARTE 0 - O QUE EXISTE DENTRO DESSES 2 ARQUIVOS
==================================================

O par TLS e formado por:
- fullchain.crt = certificado publico do servidor
- private.key = chave privada do servidor

No nosso cenario de teste, a ideia e:
- certificado X.509
- chave RSA 2048 bits
- validade de 365 dias
- CN/SAN com o IP do servidor

Exemplo do formato do certificado:

-----BEGIN CERTIFICATE-----
MIID...CONTEUDO_BASE64...ABCD
-----END CERTIFICATE-----

Exemplo do formato da chave privada:

-----BEGIN PRIVATE KEY-----
MIIE...CONTEUDO_BASE64...WXYZ
-----END PRIVATE KEY-----

Observacoes:
- o certificado pode ser compartilhado com os clientes
- a chave privada deve ficar somente no servidor
- o nginx usa os dois arquivos no handshake TLS

==================================================
PARTE 0.1 - COMO FOI GERADO NO NOSSO TESTE
==================================================

Se quiser gerar um par novo diretamente no servidor para um IP local, o comando pode ser este:

sudo openssl req -x509 -nodes -newkey rsa:2048 \
  -keyout /etc/dcriar/tls/private.key \
  -out /etc/dcriar/tls/fullchain.crt \
  -days 365 \
  -subj "/CN=192.168.0.245" \
  -addext "subjectAltName=IP:192.168.0.245,IP:127.0.0.1,DNS:localhost"

Esse comando faz tudo de uma vez:
- cria a chave privada RSA
- cria o certificado publico autoassinado
- grava os 2 arquivos ja nos caminhos esperados

Se o IP do servidor for outro, troque:
- /CN=192.168.0.245
- IP:192.168.0.245

==================================================
PARTE 1 - CRIAR A PASTA NO SERVIDOR
==================================================

No servidor:

sudo mkdir -p /etc/dcriar/tls
sudo chmod 700 /etc/dcriar/tls
sudo chown root:root /etc/dcriar/tls

==================================================
PARTE 2 - CRIAR O ARQUIVO DO CERTIFICADO
==================================================

No servidor:

sudo nano /etc/dcriar/tls/fullchain.crt

Cole o conteudo completo do certificado, por exemplo:

-----BEGIN CERTIFICATE-----
MIID...COLE_AQUI_O_CONTEUDO_REAL_DO_CERTIFICADO...ABCD
-----END CERTIFICATE-----

Se houver cadeia intermediaria, cole na mesma ordem abaixo do certificado principal.

Salvar e proteger:

sudo chmod 600 /etc/dcriar/tls/fullchain.crt
sudo chown root:root /etc/dcriar/tls/fullchain.crt

==================================================
PARTE 3 - CRIAR O ARQUIVO DA CHAVE PRIVADA
==================================================

No servidor:

sudo nano /etc/dcriar/tls/private.key

Cole o conteudo completo da chave privada, por exemplo:

-----BEGIN PRIVATE KEY-----
MIIE...COLE_AQUI_O_CONTEUDO_REAL_DA_CHAVE...WXYZ
-----END PRIVATE KEY-----

Ou, dependendo do formato:

-----BEGIN RSA PRIVATE KEY-----
MIIE...COLE_AQUI_O_CONTEUDO_REAL_DA_CHAVE...WXYZ
-----END RSA PRIVATE KEY-----

Salvar e proteger:

sudo chmod 600 /etc/dcriar/tls/private.key
sudo chown root:root /etc/dcriar/tls/private.key

==================================================
PARTE 4 - CONFERIR SE OS ARQUIVOS EXISTEM
==================================================

No servidor:

ls -l /etc/dcriar/tls

Resultado esperado:
- fullchain.crt
- private.key

==================================================
PARTE 5 - COMO O COMPOSE VAI USAR ESSES ARQUIVOS
==================================================

No .env.prod real do servidor, as variaveis devem apontar para esses caminhos:

TLS_CERT_FILE=/etc/dcriar/tls/fullchain.crt
TLS_KEY_FILE=/etc/dcriar/tls/private.key

No docker-compose.prod.yml novo, o frontend vai montar assim:

volumes:
  - ${TLS_CERT_FILE}:/etc/nginx/tls/server.crt:ro
  - ${TLS_KEY_FILE}:/etc/nginx/tls/server.key:ro

==================================================
PARTE 6 - SE OS ARQUIVOS NAO EXISTIREM
==================================================

Se FRONTEND_TLS_ENABLED=true e um desses arquivos nao existir:
- o container frontend nao sobe
- o log esperado do frontend e algo como:
  ERRO: TLS habilitado, mas certificado ou chave nao encontrados ...

Para ver isso:

docker compose \
  --env-file /etc/dcriar/.env.prod \
  -f /opt/dcriar/docker-compose.prod.yml \
  logs -f frontend

Obs.: se em algum momento o comando docker compose pull falhar com erro de autenticacao no Docker Hub, refaca o login no mesmo contexto usado pelo comando.

Se estiver usando Docker sem sudo:
docker logout
docker login -u SEU_USUARIO_DOCKER_HUB

Se estiver usando WSL/Linux com sudo:
sudo docker logout
sudo docker login -u SEU_USUARIO_DOCKER_HUB

Isso pode acontecer porque o login do Docker foi feito no usuario normal, mas o comando com sudo usa as credenciais do usuario root.

==================================================
PARTE 7 - RESUMO
==================================================

Voce precisara de 2 arquivos reais no servidor:
- /etc/dcriar/tls/fullchain.crt
- /etc/dcriar/tls/private.key

Eles serao lidos pelo frontend/nginx no startup.

Sem esses arquivos:
- HTTPS nao sobe

Com esses arquivos:
- o nginx consegue abrir a porta 443 com TLS

Resumo pratico:
- se voce quiser gerar os arquivos do zero, use o comando openssl da PARTE 0.1
- se ja tiver certificado pronto, cole o PEM do certificado em fullchain.crt
- e cole o PEM da chave privada em private.key
