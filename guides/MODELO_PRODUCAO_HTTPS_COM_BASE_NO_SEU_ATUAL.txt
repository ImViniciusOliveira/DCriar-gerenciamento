MODELO DE PRODUCAO HTTPS COM BASE NO SEU ENV/YML ATUAIS

Objetivo:
- mostrar como fica o .env.prod real depois da migracao para HTTPS
- mostrar como fica o docker-compose.prod.yml real seguindo o mesmo padrao que voce usa hoje
- mostrar como usar um unico IP do host para acesso pelo Windows/WSL
- manter o estilo atual e alterar so o necessario

==================================================

==================================================

Hoje, no que voce mandou, o frontend expõe so:

E o frontend no compose esta assim:

PARTE 2 - COMO DEVE FICAR O .env.prod REAL
==================================================

Com base no que voce mandou, a estrutura nova deve ficar parecida com isto:

APP_VERSION=1.0.0
DOCKER_REGISTRY_USER=imviniciusoliveira
BACKEND_IMAGE_NAME=dcriar-api
FRONTEND_IMAGE_NAME=dcriar-frontend

FRONTEND_HTTP_PORT=80
FRONTEND_HTTPS_PORT=443
FRONTEND_SERVER_NAME=192.168.0.250
FRONTEND_TLS_ENABLED=true
TLS_CERT_FILE=/etc/dcriar/tls/fullchain.crt
TLS_KEY_FILE=/etc/dcriar/tls/private.key

POSTGRES_DB=dcriar_prod_db
POSTGRES_USER=dcriar_prod_user
POSTGRES_PASSWORD=SENHA_REAL_DO_POSTGRES

MINIO_ROOT_USER=minio_prod_user
MINIO_ROOT_PASSWORD=SENHA_REAL_DO_MINIO
MINIO_BUCKET_NAME=dcriar-prod-bucket

CORS_ALLOWED_ORIGIN=https://192.168.0.250

MINIO_URL=http://minio-prod:9000
MINIO_ACCESS_KEY=minio_prod_user
MINIO_SECRET_KEY=SENHA_REAL_DO_MINIO
DATA_ENCRYPTION_KEY=lPAYbVW9o9HHH83/qm7hxnLJ9BlZLnxtOQMPe4kMbME=

Observacoes:
- FRONTEND_SERVER_NAME pode ser o IP neste cenario
- CORS_ALLOWED_ORIGIN deve acompanhar a origem HTTPS real do frontend
- DATA_ENCRYPTION_KEY precisa ser uma chave Base64 valida de 32 bytes para a API subir
- se depois voce mudar o acesso para outro IP ou hostname, precisa ajustar essas duas variaveis

==================================================
PARTE 3 - O QUE MUDA NO .env.prod
==================================================

Sai:
- FRONTEND_PORT=80

Entram:
- FRONTEND_HTTP_PORT=80
- FRONTEND_HTTPS_PORT=443
- FRONTEND_SERVER_NAME=192.168.0.250
- FRONTEND_TLS_ENABLED=true
- TLS_CERT_FILE=/etc/dcriar/tls/fullchain.crt
- TLS_KEY_FILE=/etc/dcriar/tls/private.key

Tambem muda:
- CORS_ALLOWED_ORIGIN=http://localhost,http://127.0.0.1,http://192.168.0.172

Para:
- CORS_ALLOWED_ORIGIN=https://192.168.0.250

==================================================
PARTE 4 - COMO DEVE FICAR O docker-compose.prod.yml REAL
==================================================

O bloco frontend deve ficar assim:

frontend:
  image: ${DOCKER_REGISTRY_USER}/${FRONTEND_IMAGE_NAME}:${APP_VERSION}
  container_name: frontend-app
  ports:
    - "${FRONTEND_HTTP_PORT}:80"
    - "${FRONTEND_HTTPS_PORT}:443"
  depends_on:
    - backend
  environment:
    FRONTEND_SERVER_NAME: ${FRONTEND_SERVER_NAME}
    FRONTEND_TLS_ENABLED: ${FRONTEND_TLS_ENABLED}
    NGINX_TLS_CERT_PATH: /etc/nginx/tls/server.crt
    NGINX_TLS_KEY_PATH: /etc/nginx/tls/server.key
  volumes:
    - ${TLS_CERT_FILE}:/etc/nginx/tls/server.crt:ro
    - ${TLS_KEY_FILE}:/etc/nginx/tls/server.key:ro
  networks:
    - dcriar-net
  restart: always

O restante do compose pode continuar no mesmo padrao atual, salvo ajustes futuros.

PARTE 5 - BLOCO COMPLETO DE EXEMPLO
==================================================

services:
  postgres-prod:
    image: postgres:14-alpine
    container_name: postgres-prod
    environment:
      POSTGRES_DB: ${POSTGRES_DB}
      POSTGRES_USER: ${POSTGRES_USER}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
    volumes:
      - postgres_data_prod:/var/lib/postgresql/data
    networks:
      - dcriar-net
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${POSTGRES_USER} -d ${POSTGRES_DB}"]
      interval: 5s
      timeout: 5s
      retries: 12
      start_period: 5s
    restart: always

  minio-prod:
    image: minio/minio:latest
    container_name: minio-prod
    environment:
      MINIO_ROOT_USER: ${MINIO_ROOT_USER}
      MINIO_ROOT_PASSWORD: ${MINIO_ROOT_PASSWORD}
    command: server /data --console-address ":9001"
    volumes:
      - minio_data_prod:/data
    networks:
      - dcriar-net
    restart: always

  minio-setup:
    image: minio/mc
    container_name: minio-setup
    depends_on:
      - minio-prod
    environment:
      MINIO_ROOT_USER: ${MINIO_ROOT_USER}
      MINIO_ROOT_PASSWORD: ${MINIO_ROOT_PASSWORD}
      MINIO_BUCKET_NAME: ${MINIO_BUCKET_NAME}
    networks:
      - dcriar-net
    entrypoint:
      - "/bin/sh"
      - "-c"
      - |-
        echo 'Esperando o MinIO ficar online...';
        until (/usr/bin/mc alias set dcriar-minio http://minio-prod:9000 $${MINIO_ROOT_USER} $${MINIO_ROOT_PASSWORD}) do
          echo '...tentando novamente' && sleep 1;
        done;
        echo 'MinIO esta online. Configurando bucket...';
        /usr/bin/mc mb dcriar-minio/$${MINIO_BUCKET_NAME} --ignore-existing;
        echo 'Bucket criado ou ja existente.';
        /usr/bin/mc anonymous set download dcriar-minio/$${MINIO_BUCKET_NAME};
        echo 'Politica do bucket definida como public (leitura publica).';
        exit 0;

  backend:
    image: ${DOCKER_REGISTRY_USER}/${BACKEND_IMAGE_NAME}:${APP_VERSION}
    container_name: backend-api
    depends_on:
      postgres-prod:
        condition: service_healthy
      minio-setup:
        condition: service_completed_successfully
    expose:
      - "8080"
    environment:
      SPRING_DATASOURCE_URL: jdbc:postgresql://postgres-prod:5432/${POSTGRES_DB}
      SPRING_DATASOURCE_USERNAME: ${POSTGRES_USER}
      SPRING_DATASOURCE_PASSWORD: ${POSTGRES_PASSWORD}
      MINIO_URL: ${MINIO_URL}
      MINIO_ACCESS_KEY: ${MINIO_ACCESS_KEY}
      MINIO_SECRET_KEY: ${MINIO_SECRET_KEY}
      MINIO_BUCKET_NAME: ${MINIO_BUCKET_NAME}
      CORS_ALLOWED_ORIGIN: ${CORS_ALLOWED_ORIGIN}
      DATA_ENCRYPTION_KEY: ${DATA_ENCRYPTION_KEY}
      SPRING_PROFILES_ACTIVE: prod
    networks:
      - dcriar-net
    restart: always

  frontend:
    image: ${DOCKER_REGISTRY_USER}/${FRONTEND_IMAGE_NAME}:${APP_VERSION}
    container_name: frontend-app
    ports:
      - "${FRONTEND_HTTP_PORT}:80"
      - "${FRONTEND_HTTPS_PORT}:443"
    depends_on:
      - backend
    environment:
      FRONTEND_SERVER_NAME: ${FRONTEND_SERVER_NAME}
      FRONTEND_TLS_ENABLED: ${FRONTEND_TLS_ENABLED}
      NGINX_TLS_CERT_PATH: /etc/nginx/tls/server.crt
      NGINX_TLS_KEY_PATH: /etc/nginx/tls/server.key
    volumes:
      - ${TLS_CERT_FILE}:/etc/nginx/tls/server.crt:ro
      - ${TLS_KEY_FILE}:/etc/nginx/tls/server.key:ro
    networks:
      - dcriar-net
    restart: always

volumes:
  postgres_data_prod:
  minio_data_prod:

networks:
  dcriar-net:
    driver: bridge

PARTE 6 - O QUE SERA TESTADO DEPOIS
==================================================

Depois de aplicar essa configuracao:
- https://192.168.0.250 deve abrir a aplicacao
- http://192.168.0.250 deve redirecionar para https://192.168.0.250
- o frontend deve continuar falando com /api normalmente
- o backend continua interno no compose

Obs.: se o docker compose pull falhar com erro de autenticacao no Docker Hub, refaca o login no mesmo contexto usado pelo comando.

Se estiver usando Docker sem sudo:
docker logout
docker login -u SEU_USUARIO_DOCKER_HUB

Se estiver usando WSL/Linux com sudo:
sudo docker logout
sudo docker login -u SEU_USUARIO_DOCKER_HUB

Isso pode acontecer porque o login do Docker foi feito no usuario normal, mas o comando com sudo usa as credenciais do usuario root.

==================================================
PARTE 7 - COMO USAR UM UNICO IP DO HOST NO WINDOWS + WSL
==================================================

Objetivo:
- fazer os acessos da rede usarem apenas o IP do host Windows
- evitar depender de IP interno variavel do WSL

Padrao recomendado:
- definir IP fixo no host Windows
- publicar a aplicacao por esse IP
- usar esse mesmo IP em:
  - FRONTEND_SERVER_NAME
  - CORS_ALLOWED_ORIGIN

Exemplo:
- IP fixo do host Windows: 192.168.0.172

Entao:
- FRONTEND_SERVER_NAME=192.168.0.172
- CORS_ALLOWED_ORIGIN=https://192.168.0.172

Com isso, o acesso esperado da rede fica:
- http://192.168.0.172 -> redirect para HTTPS
- https://192.168.0.172 -> aplicacao real

Se o Docker publicar 80 e 443 corretamente no host Windows, esse IP unico ja resolve.

Se o teu ambiente Windows 10 + WSL ainda nao expuser 80 e 443 para a rede local, ai sim pode ser necessario manter portproxy para:
- 80
- 443

Nesse caso, o objetivo continua o mesmo:
- um unico IP do host Windows visivel para a rede

==================================================
PARTE 8 - RESUMO
==================================================

Com base no seu padrao atual, a migracao para HTTPS exige basicamente:
- trocar FRONTEND_PORT por FRONTEND_HTTP_PORT e FRONTEND_HTTPS_PORT
- adicionar FRONTEND_SERVER_NAME
- adicionar FRONTEND_TLS_ENABLED
- adicionar TLS_CERT_FILE e TLS_KEY_FILE
- trocar CORS_ALLOWED_ORIGIN para a origem HTTPS final
- montar os 2 arquivos TLS no frontend
